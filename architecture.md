# Architecture

## Overview

`isubscribe-widget-react` is a self-contained React component library. One public component (`SubscriptionWidget`) handles data fetching, state, and rendering. It ships as dual CJS + ESM bundles with TypeScript declarations.

---

## Directory layout

```
src/
  index.ts                      # Public API — re-exports only
  SubscriptionWidget.tsx        # All component logic (see below)
  SubscriptionWidget.module.css # Scoped styles + CSS custom property tokens
  types.ts                      # Data model interfaces
  global.d.ts                   # CSS module type shim

dist/                           # Built output (not committed)
  index.js                      # CommonJS bundle
  index.esm.js                  # ES module bundle
  index.d.ts                    # Aggregated TypeScript declarations

rollup.config.js                # Three-target build
tsconfig.json                   # Strict ES2024, noEmit
```

---

## Component tree

```
SubscriptionWidget   (forwardRef — public export)
│
│  owns: subscriptions[], loading, error, reloadKey
│  exposes via ref: refetch()
│
└── SubscriptionCard   (module-private FC, one per plan)
    ├── Sale badge         (conditional — isOnSale && price reduced)
    ├── Title
    ├── Description        (optional)
    ├── Price block
    │   ├── Original price (strikethrough, conditional)
    │   └── Effective price
    ├── Duration
    ├── Features list      (optional)
    │   └── Feature item × N
    │       ├── Icon       (node | render-prop | null)
    │       └── Trial badge (conditional)
    ├── Trial note         (conditional — any feature has trial)
    └── Subscribe button
```

## Data flow

```
apiKey + apiBaseUrl
       │
       ▼
  fetch (AbortController)
       │
   ┌───┴────────────────────────────┐
   │ ok                          error │
   ▼                                ▼
subscriptions[]               error state
   │                                │
   ▼                                ▼
SubscriptionCard × N         error slot render
       │
  onSubscribe(plan)
```

Re-fetch is triggered by incrementing `reloadKey` (state), which is a `useEffect` dependency. Calling `ref.refetch()` increments it from outside.

AbortController cancels in-flight requests on unmount or on re-fetch before the previous request completes.

---

## State

All state lives in `SubscriptionWidget`. `SubscriptionCard` is stateless.

| State | Type | Purpose |
|-------|------|---------|
| `subscriptions` | `Subscription[]` | Fetched plans |
| `loading` | `boolean` | Shows loader slot while fetching |
| `error` | `Error \| null` | Shows error slot on failure |
| `reloadKey` | `number` | Increment to trigger re-fetch |

Callbacks (`onSubscribe`, `onError`, `onLoaded`) are stabilized via `useRef` wrappers so they never appear as `useEffect` dependencies, preventing infinite fetch loops when callers pass inline functions.

---

## Styling architecture

CSS Modules provide local scope. All visual tokens are exposed as CSS custom properties (`--isw-*`) declared on the container element. The host app can override any token via:

- `style` prop (inline — highest specificity)
- A wrapping selector in host CSS

Slot class names (`classNames` prop) let hosts append their own classes to any rendered region without breaking built-in styles.

Layout uses CSS Grid with `auto-fill` + `minmax(280px, 1fr)` for responsive card wrapping with no JS breakpoints.

## Build system

Rollup produces three outputs from a single pass:

| Output | Format | Purpose |
|--------|--------|---------|
| `dist/index.js` | CJS | Node.js / legacy bundlers |
| `dist/index.esm.js` | ESM | Vite, webpack 5, esbuild |
| `dist/index.d.ts` | DTS | TypeScript consumers |

React and ReactDOM are external (peer dependencies) — never bundled.

CSS Modules are processed by PostCSS, minimized, and injected into the JS bundle as a side-effect import. `sideEffects: ["*.css"]` in `package.json` prevents tree-shakers from dropping styles.

TypeScript declarations are generated by `rollup-plugin-dts` in a separate Rollup pass that reads the `.d.ts` files emitted by `@rollup/plugin-typescript`.

## Public API surface

```ts
// Component
export { SubscriptionWidget }

// Types
export type {
  SubscriptionWidgetProps,   // Component props
  SubscriptionWidgetHandle,  // ref shape: { refetch(): void }
  SubscriptionWidgetSlot,    // Union of 18 slot name strings
  SubscriptionWidgetLabels,  // i18n label overrides
  Subscription,              // API data model
  Feature,                   // Feature item inside Subscription
}
```

Everything else is internal. `SubscriptionCard` and utility functions (`cx`, `formatMoney`) are not exported.

---

## Key design decisions

**Single-file component** — `SubscriptionWidget.tsx` contains the main component, the internal `SubscriptionCard`, and two small utilities. Avoids premature file splitting for a library with one public export.

**No external state or context** — the component is fully self-contained; host apps do not need a provider.

**Stable callback refs** — avoids requiring consumers to `useCallback` every prop they pass, making the API friendlier.

**CSS custom properties over JS theming** — zero runtime cost, works across Shadow DOM boundaries if needed, and lets designers use browser DevTools directly.

**`Intl.NumberFormat` for currency** — locale-aware, no extra dependency. Falls back to `${price} ${currency}` if `Intl` is unavailable.
